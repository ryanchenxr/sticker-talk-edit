# 动态贴纸与闪卡材质

本规范定义字体角色、emoji、虹彩细闪和整贴轻摆的制作方法。参数可根据具体画面调整。

## 先按语义选择字样

| 角色 | 字体与材质 | 运动 |
| --- | --- | --- |
| 主题、章节大编号、强数字 | 圆润粗体；虹彩字面、蓝描线、银彩细闪底纸 | 小幅前后倾斜与轻摆，虹彩/反光连续缓慢变化 |
| 关键词、肯定/否定、普通列表 | 圆润蓝字；带极轻珠光色的浅色模切底纸 | 整张贴纸轻摆，阴影跟随；没有满屏强闪粉 |
| 一句注释、引语、列表引导语 | 真实手写字体，笔画较轻，字势自然 | 少量倾角与更轻的摆动 |
| 左上角章节标签 | 清晰圆体，编号与短名紧凑组合 | 接近静止；幅度明显小于主要贴纸 |
| 连续字幕（仅用户需要时） | 高可读字体和稳定基线 | 不把重点贴纸的持续摇摆套给全部逐句字幕 |

圆润不是把方黑体描粗。中文要实际试排；检查字腔、标点、英文和数字，缺字造成的回退字体混用必须处理。手写注释应使用真实存在的手写字体，不能只把主字体斜切。手写字较细时适当增加字号或很轻地加厚笔画。

同一条片通常选一款主要圆体、一款手写注释字体，再给数字/英文选择协调字形。先检查实际字体可用性；替代字体应保持字形清晰和角色层级。字体由用户或所在环境提供。

## emoji 是语义的一部分

- 先看原话：疑问/思考 → 🤔；拆解/结构 → 🧩；录制/视频 → 🎬；想法/理解 → 💡；明确喜爱 → 😍；乏味或卡住的过程可用 🫠。这些是例子，不是必须匹配的词典。
- 每组通常一个 emoji，一屏通常 1–2 个主 emoji 组；单独 emoji 可以作为反应贴纸。纯编号列表已经有编号时，不强行再加一列图标。
- emoji、文字、编号作为一组，共用模切底纸和阴影，并一起运动。emoji 可略大于字高，但不能抢过关键结论。
- 明确否定可用划线、禁止符号或叉号；“不只是 A”不是“禁止 A”，不能误画成否定。
- 彩色 emoji 需要支持彩色字体的渲染路径，或使用有来源、可使用的透明图。把 emoji 当普通字形转轮廓可能丢失彩色位图；必须检查实际输出，不能出现空白或方框。
- 使用当前环境提供的彩色字体或具备适当授权的图标素材。

## 闪卡是一个材质系统

从后到前分为：柔和投影 → 随词组轮廓裁切的银彩底纸 → 固定细闪颗粒 → 彩色字面 → 清楚的蓝色字边。底纸要连成一张，不能只有逐字白描边或一块笨重矩形。

1. **稳定的底色。** 用银灰与粉、青、紫、浅绿形成柔和虹彩，保留材质的明暗。普通关键词只用很轻的珠光色，主标题与大编号才用完整闪卡。
2. **缓慢变色。** 用低频、连续的颜色偏移模拟视角变化，不在两个纯色之间切换，也不做饱和度过高的循环跑马灯。
3. **宽而柔和的反光。** 反光带轻扫过字面与底纸，方向与贴纸轻倾相协调；不能把整张字卡漂白。
4. **颗粒附着表面。** 先生成固定种子的细颗粒，颗粒位置随贴纸一起动，只缓慢改变亮度。每一帧重新生成随机噪点会变成电视雪花，不是闪卡。
5. **阅读边界固定。** 蓝色描线保持足够对比，细闪不侵蚀字形。颜色转换需要正确处理工作色域，不能因为线性 RGB 与 sRGB 混用而把深蓝洗成灰紫。

在 1080p 下可从约 1 px 的多数颗粒、少量更亮点试起。不要用满屏十字星、镜头眩光或爆炸粒子替代细闪。人物肤色、背景网格与素材截图不跟着贴纸变色。

## 入场后仍然轻动

轻摆的单位是**整张贴纸**，包括字、emoji、底纸与阴影。不能每个汉字各自抖动。

| 参数 | 建议起点 |
| --- | --- |
| 入场 | 0.15–0.30 秒淡入与轻缩放，可有一次小幅倾角收束 |
| 主要单贴停留 | 平面旋转约 ±0.6–1.3°，上下约 ±1–3 px |
| 前后/左右轻倾 | 透视倾角约 ±1–3°，长句降低幅度 |
| 列表行 | 每行平面旋转约 ±0.4–0.8°，各自不同相位 |
| 角标 | 约 ±0.15–0.3°、不到 1 px 的浮动，或直接稳定 |
| 运动周期 | 约 3–6 秒，连续往复；用稳定 id 决定不同相位 |
| 虹彩与反光 | 约 3–8 秒的缓慢变化，允许与运动节奏略有错开 |

列表仍然讲到一条才出现一条。新增项不能推着已出现的行反复跳位置；每行的阅读中心、顺序和间距固定。可有整体极轻的倾斜，但不能只让列表整个容器像一块板一样转动。

布局检查使用完整运动包围盒：包括极限倾角、浮动、阴影和 emoji。角度变化不应压到人脸、相邻行或字幕。长句、说明性小字和连续字幕优先减少运动。用户明确要求静态或少动时，以其要求为准。

## macOS 可复用组件

仓库的 `scripts/StickerKit.swift` 提供 `StickerSpec` 和 `StickerKit.image(_:elapsed:motion:)`：

```swift
let kit = try StickerKit(
    roundedFont: "STYuanti-SC-Bold",
    handFontFile: "/path/to/your-handwriting-font.ttf"
)
let spec = StickerSpec(
    id: "point-structure", text: "拆出结构",
    kind: .plain, size: 80, emoji: "🧩"
)
let sticker = kit.image(spec, elapsed: timelineTime - cueStart)
// sticker 是有透明边距的 CIImage；将其中心放到画面预留位置后合成。
```

支持 `hero`、`plain`、`hand`、`list`、`badge`、`negative`。列表的编号通过 `number` 单独传入。文本、emoji 和编号保持为源数据，可重新排版。

- 每帧调用 `image` 更新 `elapsed`；只缓存字形和底纸遮罩，不缓存最终动态图像为单张 PNG。
- `elapsed` 从该贴纸的入场开始累计，稳定 `id` 决定其纹理与运动相位。跳到同一时间点必须得到同一画面。
- `motion: false` 只关闭几何轻摆；完全静态时同时固定 `elapsed`。人物、时间线和出场时机仍由实际剪辑器负责。
- 组件使用本机 AppKit、CoreText、Core Image 和 Metal，字体与 emoji 从系统或指定字体文件加载。
- 默认圆体为本机的 `STYuanti-SC-Bold`，纯英文/数字强调使用 `ArialRoundedMTBold`。字体实际不可用时应更换参数；未提供手写字体时，演示会明确提示降级为圆体。
- 该 Swift 组件面向 macOS；其他系统或编辑器可按相同材质与动效规范实现。

生成 18 秒无声样片（从仓库根目录运行，需要 Swift Command Line Tools）：

```bash
swiftc -O scripts/StickerKit.swift scripts/render_sticker_demo.swift \
  -o /tmp/sticker-demo
/tmp/sticker-demo --output /absolute/output/sticker-demo.mp4 \
  --hand-font /absolute/path/to/your-handwriting-font.ttf
```

输出包括 MP4 和带输出文件名前缀的代表帧。演示不覆盖已有 MP4；还检查相同时间重复渲染的一致性与不同时间的动态变化。

## 验证要求

先看正常尺寸，再看缩小预览；用正常播放评估动感，用相隔约 0.1 秒的连续帧检查跳动，用相隔约 1–2 秒的帧检查颜色与反光变化。

确认彩色 emoji 完整、手写注释可读、纸边圆润、闪粉附着、蓝字不被洗白、列表逐行独立轻摆。用静态画面核对字形与材质，用实际导出的视频检查动态变化和阅读节奏。
